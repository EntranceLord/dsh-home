# 0008 — 计划协议放在插件里，不写进 AGENTS.md

## 结论

「暂停 / 完成 / Notes / 提醒」这套计划协议由 dsh-home 插件承担，分三层：

1. **静态系统提示段落**（`systemPrompt.section`，order `9500`）——协议始终在场，随插件版本走；
2. **复合工具** `plan_scenario`（pause / finish）——多步写入在宿主里一次事务完成；
3. **回合守卫**——根会话里用户说了暂停/完成的词而该回合计划没变时，注入一条提醒。

用户级 `~/.dsh/AGENTS.md` 不写入计划协议；技能 `home-plan` 只保留细节与教学，不承担强制。

## 为什么

- 技能与 AGENTS.md 都是提示词层面：可能没加载、可能被忽略，而且 AGENTS.md 会进入所有会话的上下文。
- 需要「说人话也能稳定触发」的场景，只能靠更强的机制：
  - 插件注入的提示段落在每个会话都在场，且只随插件启停；
  - 复合工具把「改日期 + 建行程事件 + 返回未完成」压成一次工具调用，模型没有拼错步骤的空间；
  - 守卫用代码比对「用户说了暂停/完成」与「计划 revision 是否变化」，模型漏掉时补一条提醒。
- 但「把用户说的『пауза』判定为暂停」终究是模型的决定。守卫让漏掉变得罕见且可见，不能保证 100%。真正确定性的只有以后的 UI 路径（按钮、命令）。

## 已知代价

- 提示段落是每会话固定 token 成本（约 120 tokens）；文本静态，不破坏 KV 缓存前缀。
- 守卫按关键词子串匹配，有误报可能；误报只注入一条提醒，不写计划。关键词可配置。
- 子代理会话按 `session.header.origin === 'subagent'` 跳过，避免污染被委派的工作。
